# Навыки карточек (v1)

Персональный навык конкретного экземпляра карточки игрока: максимум один навык, уровни I/II/III,
назначается игроком за жетоны этого навыка. Навык усиливает **одно конкретное событие матча**
и не меняет рейтинг карточки.

## Где что лежит

| Что | Где |
|---|---|
| Навык экземпляра | `user_cards.skill_code` / `user_cards.skill_level` (NULL/NULL = нет навыка) |
| Каталог (что делает навык, макс. набор позиций, поддержка движком) | `backend/app/services/card_skill_catalog.py` |
| Состояние каталога, которое меняет админ (вкл/выкл, сужение позиций, порядок) | таблица `card_skills` |
| Сила уровней, предел бонуса, границы вероятности, все цены, глобальный флаг, жетоны за места в турнире | `game_config` (`card_skill_*`, `card_skills_enabled`, `ptour_place_skill_tokens`) |
| Баланс жетонов | `user_skill_tokens` (строка создаётся при первой выдаче) |
| Журнал выдач и операций (+ идемпотентность) | `card_skill_ledger` (уникальный `(user_id, idempotency_key)`) |
| Расчёт эффектов в матче | `backend/app/services/card_skill_effects.py` |
| Операции / выдачи / защита жизненного цикла | `backend/app/services/card_skill_service.py` |
| API игрока | `/api/v1/card-skills/*` |
| API админа | `/api/v1/admin/card-skills/*` + экономика через `PUT /api/v1/admin/games/config` |
| Админка | «Навыки карточек» (`/admin/card-skills`), награда жетонами — в «Заданиях» |

## Где навыки действуют

Порядок расчёта везде одинаковый: рейтинг → тренер/стадион/тренировка (через рейтинги и профиль
команды) → базовая вероятность конкретного броска по существующей кривой → `+N п.п.` навыка
(сумма однонаправленных бонусов ≤ `card_skill_event_bonus_cap_pp`) → границы
`[floor, ceiling]` (применяются только если навык сдвинул вероятность и не обрезают базовое
значение, уже лежащее за границей). Тренеры и стадионы на сами эти броски не действуют, поэтому
двойного применения нет.

| Навык | Позиции (макс.) | Card Arena | Турниры игроков |
|---|---|---|---|
| Снайпер | ST, LW, RW, LM, RM, CAM | бросок промаха своего бьющего и принимающего после паса | промах бьющего, принимающего после паса, выхода один на один |
| Дриблёр | LW, RW, LM, RM, ST, CAM | — (нет события обыгрыша) | доля исхода «прорыв» в дуэли этапа 1 (атака и контратака) |
| Диспетчер | CM, CAM, CDM | бросок неудачного паса пасующего | бросок неудачного паса пасующего |
| Перехватчик | CB, LB, RB, CDM | — (защитник соперника не персонифицирован) | тот же бросок паса со стороны защитника эпизода |
| Воздушный король | CB, ST | **недоступен**: в движке нет верховых единоборств | **недоступен** |
| Реакция | GK | сейв своего вратаря и вратаря соперника (если у его карты навык), включая пенальти | бросок сейва команды этого вратаря, включая пенальти (база по‑прежнему от рейтинга защитника эпизода) |

Клубные турниры используют клубные карточки (`club_cards`), у которых навыков нет. Мини-игры
(Тактико, пенальти, штрафной, слова, память и т.д.) навыки не затрагивают.

Снимок эффектов фиксируется при старте матча: Card Arena — `matches.server_state["skills"]`,
турнир игроков — `player_tournament_matches.skill_snapshot`. Старые матчи без снимка играются
без эффектов. В журнале событий навык показывается только если участвовал в броске; «решил исход»
— только если тот же случайный бросок без навыка дал бы другой результат.

## Стартовая экономика

| Операция | Жетоны | Монеты |
|---|---|---|
| Назначение (уровень I) | 1 | 0 |
| I → II | 2 | 400 |
| II → III | 4 | 1200 |
| Замена (новый навык с уровня I, старый уничтожается без возврата) | 1 | 300 |

Бонусы уровней: I = 2 п.п., II = 4, III = 6; предел на событие 8 п.п.; границы 2–95 %.
Жетоны — главный ограничитель (их источники настраивает админ), монеты — сток: полный путь до III
стоит 1600 монет ≈ 2 элитных пака (800) или ≈ 16 побед в турнире игроков (100), тогда как бонус
действует лишь в доле эпизодов одной карточки.

## Отключение и обновление

* **Выключить механику без деплоя:** админка → «Навыки карточек» → снять «Механика навыков
  включена». Операции недоступны, новые матчи — без эффектов; навыки и жетоны сохраняются, начатые
  матчи доигрываются по зафиксированным правилам.
* **Закрыть один навык:** снять «Доступен для получения». Его нельзя назначить, улучшить или выбрать
  при замене; уже полученный навык остаётся и действует, заменить его на другой можно.
* **Обновление:** `docker compose exec backend alembic upgrade head` (ревизия `0122_card_skills`).
  Миграция только добавляет nullable-колонки/таблицы и сид каталога (`ON CONFLICT DO NOTHING`),
  существующие карточки не меняются.
* **Откат кода:** `alembic downgrade 0121` намеренно ничего не удаляет (данные игроков
  сохраняются, старый код их игнорирует); повторный `upgrade head` идемпотентен.
* Бот (`bot/`) не трогает новые колонки: его `INSERT INTO user_cards` перечисляет столбцы явно,
  новые — nullable.

## Ограничения v1

* «Воздушный король» выключен до появления в движке верхового единоборства (см. `remaining_work`
  в каталоге).
* Жетоны не продаются за Stars и не выдаются за премиум-задания (бот при отписке откатывает только монеты).
* Источники жетонов: обычные задания, места в турнире игроков, паки, ручная выдача админом.

## Жетоны в паках

Тот же принцип, что у стадионов (ревизия `0123_pack_skill_tokens`):

* у каждого пака есть «Шанс жетона навыка вместо игрока» (`packs.skill_token_drop_chance`) —
  бросок на каждый слот, общий с шансами тренера и стадиона (проверяется последним);
  100% = «пак навыков», где каждый слот — жетоны; 0 (по умолчанию) — пак как раньше;
* какой навык выпал — по весам в «Навыки карточек → Жетоны в паках»
  (`card_skills.pack_drop_weight`, 0 = не выпадает), сколько жетонов — `pack_drop_quantity`;
  закрытые для получения навыки не выпадают; если выпадать нечему — слот остаётся игроком;
* слот с бриллиантовой редкостью всегда остаётся игроком (как у стадионов);
* работает во всех путях открытия пака (покупка, массовое открытие, бесплатный пак, пак из
  чата, задания, подарки, колесо). Начисление — в той же транзакции, что и открытие, журнал
  `card_skill_ledger` с видом `grant_pack`; повтор с тем же ключом идемпотентности возвращает
  те же жетоны без повторного начисления;
* откат `0123` удаляет только записи «слот = жетоны» из истории открытий; сами жетоны остаются.
